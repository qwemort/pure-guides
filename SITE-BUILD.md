# Как устроено обновление сайта (и куда растём)

Идея: правду хранить в одном месте, страницы собирать из неё, проверять машиной. Руками правится только источник.

## Сделано (14.11.2026)
- Шапка и подвал: `templates/`, ставит `build.py` (`tools/site-chrome.py` оставлен как обёртка).
- `tools/site-check.py` + Action `site-check`: на каждый пуш ловит отсутствие шапки/подвала, битые ссылки, устаревшие факты (Pro, «3 тайтла», «52»), расхождение «N ready lists» с числом страниц в `block/`, страницы вне sitemap, нет title/description/canonical, длинные тире, неполные и кривые переводы `i18n/`.
- Числа списков на главной в маркерах `<!--n-->…<!--/n-->`: обновляет `gen-block.mjs` сам.
- Группы тайтлов (шрифты, плашки, раскрытие) собирают генераторы, вид один на главной, `block/`, `mute-list/`.
- `i18n/home.en.json`: текст главной по ключам, `i18n/PROMPT-translate.md`: промпт для перевода на 12 языков.

## Шаги 1 и 2 сделаны (14.11.2026): одна команда, факты, шаблоны
Команда: `python3 tools/build.py --words <words.js из репозитория расширения>` (для ботов `--no-generate --no-check`). Порядок: генераторы тайтлов → факты → шапка и подвал → `site-check`. Все автозапуски (`mutelists`, `spoiler-index`, `spoiler-danger`) заканчиваются этой командой, повторный запуск ничего не ломает.
- `data/facts.json`: ссылки магазинов и репозитория, дата релиза GTA VI, почта. Число списков считается само по `block/`.
- Любая ссылка на магазин на любой странице сама получает метку `data-href="chrome:top"` и каждый раз берётся из `facts.json`. Сменился ID или адрес: правка в одной строке, `build.py` пересобирает все страницы. Проверено: один факт сменился, 139 страниц обновились.
- Дата релиза: `data-release` на `<html>` главной берётся из фактов, обратный отсчёт считает скрипт.
- `templates/header.html`, `templates/footer.html`: шапка и подвал с токенами `{{root}}`, `{{home}}`, `{{link:chrome:top}}`, `{{fact:email}}` и `{{t:ключ}}`. Тексты шапки и подвала уже берутся из `i18n/home.<язык>.json`, значит перевод ляжет в них без правки шаблонов.
- `site-check` теперь ещё сверяет метки ссылок с `facts.json` и находит ссылки на магазины, которых в фактах нет.

## Шаг 3a сделан (14.11.2026): главная на 13 языках
`build.py` шаг `lang`: из английской `index.html` + `i18n/home.<язык>.json` собирает `/<язык>/index.html` (de es fr it ja ko pl pt-br ru tr uk zh-cn), с `hreflang`, переключателем языка внизу и записью в sitemap. Английский текст в `index.html` сверяется с `home.en.json` (правка руками без JSON ломает сборку). Тексты JS (погода, обратный отсчёт, демо) берутся из `window.PURE_I18N`, множественное число по CLDR. Новый язык: положить `i18n/home.<язык>.json`, добавить в `LANGS` в `build.py`, запустить сборку. Названия тайтлов и ссылки из групп ведут на английские страницы `block/`.

## Шаг 3: языки (de en es fr it ja ko pl pt-BR ru tr uk zh-CN, как в расширении)
- Источник текста: `i18n/<страница>.<язык>.json`, проверка `site-check` не пускает потерянные плейсхолдеры, формы множественного числа, названия брендов и тег `<b>`.
- Сборка кладёт английский в корень, остальные в `/<язык>/…`, добавляет `hreflang`, переключатель языка и sitemap по языкам.
- Порядок: главная → 3 главные страницы (гайд GTA 6, `block/gta6`, демо) → страницы тайтлов только для языков, где есть трафик (смотреть панель Chrome по странам).
- Осторожно: 13 языков на 120 страниц тайтлов это 1500+ похожих страниц. Google может счесть их слабыми. Поэтому сначала спрос, потом объём.

## Шаг 4: статьи
Гайды как `content/<slug>.<язык>.html` с коротким заголовком-описанием и общим макетом. Новая статья или перевод = один файл.

## Правило для всех шагов
Новая страница или генератор не вставляет шапку/подвал сам: их ставит `site-chrome.py`. Новый факт сначала в источник, потом в страницы.
