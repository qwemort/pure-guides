ModHeader was removed from Chrome and Edge. Here is how to move your header profiles in 2 minutes

Last updated: 25 October 2026

Disclosure: I build PureHeaders, one of the replacements mentioned below. I have tried to keep the facts and the checklist useful whichever tool you choose. Other options are listed at the end.

What happened

ModHeader, a popular extension for changing HTTP request and response headers, had more than 1.6 million installs (roughly 900,000 on Chrome and 700,000 on Edge). In 2026 security researchers at Stripe OLT reported that version 7.0.18 contained a hidden data-collection module: code that could gather the domains you visit, encrypt them and upload them to a remote server once a day. According to the report the collector was switched off by default, but the code, key and schedule were already inside the extension. The extension also showed ads and opened advertising tabs after updates.

Microsoft removed ModHeader from Edge Add-ons and Google removed it from the Chrome Web Store on 10 July 2026. Reports differ on the exact Edge date (June or July 2026). TechRadar has a summary.

Is it still in your browser?

Very likely, yes. Removing an extension from a store does not remove it from browsers where it is already installed. Check:

  • Chrome: open chrome://extensions
  • Edge: open edge://extensions

If ModHeader is there, export your profiles first (next section), then remove it.

Step 1 — export your profiles from ModHeader

  1. Open ModHeader.
  2. Choose Export → Export JSON → Download JSON. You get a .json file with your profiles.
  3. Now remove ModHeader from chrome://extensions or edge://extensions.

The file contains your header values. If some are tokens or API keys, keep the file somewhere private and delete it after importing.

Step 2 — before you pick a replacement, check these five things

A header extension sits in the path of your web traffic, so a bad one can do a lot of damage. Whatever you choose, check:

  1. Site access. Does it ask for access to all websites at install, or only to the sites you add?
  2. Its own network requests. In chrome://extensions, turn on Developer mode, open the extension's service worker and watch the Network tab while you use it. A header tool has little reason to talk to a server.
  3. Remote configuration. Can behaviour be switched on later from a server, without an update? That is exactly how a dormant collector works.
  4. Unrelated code. Ads, analytics or other bundled SDKs have no place in a header tool.
  5. Where your values are stored. Tokens should stay on your device, not be synced to someone's cloud.

Step 3 — import into PureHeaders

PureHeaders reads ModHeader JSON exports (the classic format and the newer "sections" format) and the import is free.

  1. Install PureHeaders: Microsoft Edge. Firefox is in review and Chrome is coming; this page will be updated when they are live.
  2. The welcome page opens with an Import a JSON export button. Later you can use Import in the popup.
  3. Pick the file from step 1. You get a short report of what was imported and anything that did not carry over. Nothing you already have is overwritten.
  4. Add the sites the rules should work on. PureHeaders has access to no sites at install and asks for each site you add.

What does not carry over: ModHeader values written as function(...) are imported switched off, because PureHeaders never runs code from an imported file. You will see them in the report.

A note on CORS

Many "Allow CORS" extensions set Access-Control-Allow-Origin: * for every site. That has two problems: browsers reject * for requests with cookies, so logged-in API calls still fail, and switching it on for the whole web lets any page read responses from sites you are logged into. PureHeaders' Fix CORS works for one page → the API sites you choose, sends the exact origin instead of * and adds Access-Control-Allow-Credentials: true, so requests with cookies work.

Honest limits: an extension cannot change the server's status code, so if the server answers the preflight (OPTIONS) with an error, the browser will still block the request. Cookies to another site may also be blocked by SameSite rules or third-party cookie settings.
